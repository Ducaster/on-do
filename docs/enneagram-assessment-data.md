# 성격유형 검사(에니어그램) 구현 명세

이 문서는 다른 서비스나 프로젝트에 동일한 성격유형 검사 기능을 구현할 수 있도록 정리한 독립 명세서입니다. 특정 프레임워크, 저장소, 라우팅 구조에 의존하지 않습니다.

포함 내용:

- 99개 검사 문항
- 문항별 유형 매핑
- 일반/역채점 규칙
- 주 유형, 날개, 통합/분열 방향 계산 방식
- 결과 저장 JSON 예시
- 유형별 결과 해석 데이터
- 제출/저장 흐름 예시

## 1. 검사 개요

- 검사명: 성격유형 검사
- 기반: 에니어그램 9유형
- 문항 수: 99문항
- 구성: 9개 그룹 x 11문항
- 각 그룹: 일반 문항 10개 + 역채점 문항 1개
- 응답 척도: 1~5점 리커트 척도

| 응답값 | 라벨 | 일반 문항 점수 | 역채점 문항 점수 |
|---:|---|---:|---:|
| 1 | 전혀 아니다 | 1 | 5 |
| 2 | 아니다 | 2 | 4 |
| 3 | 보통이다 | 3 | 3 |
| 4 | 그렇다 | 4 | 2 |
| 5 | 매우 그렇다 | 5 | 1 |

## 3. 채점 로직

### 3.1 문항별 점수 반영

```ts
const raw = answers[answerIndex] ?? 3;
const value = qIdx === 10 ? 6 - raw : raw;
total += value;
```

- 각 그룹은 11문항입니다.
- 각 그룹의 마지막 문항, 즉 `questionIndex === 10`, 은 역채점입니다.
- 미응답 값이 채점 로직에 들어오면 중간값 `3`으로 처리할 수 있습니다.
- 권장 UI 동작: 다음/제출 단계에서 미응답 문항을 막고, 해당 문항으로 자동 스크롤합니다.

### 3.2 유형별 점수

```ts
scores[enneagramType] = total;
```

- 유형별 원점수 범위: 11~55점
- 최대 점수: `11문항 x 5점 = 55점`
- 시각화 백분율:

```ts
percentages[t] = Math.round((scores[t] / 55) * 100);
```

### 3.3 주 유형 결정

```ts
for (let t = 1; t <= 9; t++) {
  if (scores[t] > maxScore) {
    maxScore = scores[t];
    maxType = t;
  }
}
```

- 1~9유형 중 최고 점수 유형이 주 유형입니다.
- 동점이면 먼저 발견된 낮은 번호 유형이 유지됩니다. 예: 3유형과 5유형이 동점이면 3유형.

### 3.4 날개 유형 결정

```ts
const left = mainType === 1 ? 9 : mainType - 1;
const right = mainType === 9 ? 1 : mainType + 1;
return scores[left] >= scores[right] ? left : right;
```

- 주 유형의 인접 유형 두 개 중 점수가 높은 유형이 날개입니다.
- 동점이면 왼쪽 유형을 선택합니다.
- 예: 주 유형이 5이면 후보는 4와 6, 동점이면 4가 날개입니다.

## 6. 제출/저장 흐름 예시

1. 검사 화면에서 99개 응답을 `answers` 배열로 수집합니다.
2. 제출 시 사용자/내담자 식별자와 `answers`를 백엔드 또는 저장 처리 함수에 전달합니다.
3. 채점 함수가 유형별 점수, 주 유형, 날개, 통합/분열 방향, 백분율을 계산합니다.
4. 검사 요약 저장소에 결과 JSON과 결과 메모를 저장합니다.
5. 상세 응답 저장소에 원본 응답 배열과 유형별 점수를 별도로 저장합니다.
6. 저장 후 결과 상세 화면으로 이동하거나, 저장된 `assessmentId`를 반환해 결과 조회에 사용합니다.

### 6.1 검사 요약 저장 권장 필드

검사 목록, 내담자 상세, 결과 조회에 필요한 최소 필드입니다.

| 필드 | 설명 |
|---|---|
| assessmentId | 검사 결과 고유 ID |
| subjectId | 검사 대상자/내담자 고유 ID |
| assessmentType | 검사 종류. 예: `personality` |
| assessmentName | 표시명. 예: `성격유형 검사` |
| submittedAt | 제출일 또는 제출 시각 |
| result | 결과 JSON. `mainType`, `wing`, `scores`, `percentages` 포함 |
| note | 요약 메모. 예: `5유형(탐구자) / 날개: 6유형` |

### 6.2 상세 응답 저장 권장 필드

응답 재분석, 검증, 결과 재생성을 위해 원본 응답을 함께 저장하는 것을 권장합니다.

| 필드 | 설명 |
|---|---|
| assessmentId | 검사 결과 고유 ID |
| subjectId | 검사 대상자/내담자 고유 ID |
| submittedAt | 제출일 또는 제출 시각 |
| answers | 99개 응답 배열. 예: `[4, 3, 5, ...]` |
| mainType | 주 유형 번호 |
| wing | 날개 유형 번호 |
| scores | 유형별 원점수 JSON |
| percentages | 유형별 백분율 JSON |

저장 매체는 관계형 DB, NoSQL, 스프레드시트, 파일 저장소 등 어떤 방식을 써도 됩니다. 핵심은 `answers`, `scores`, `mainType`, `wing`을 함께 보존하는 것입니다.

## 7. 결과 화면 표시 데이터

결과 화면은 결과 JSON과 이 문서의 유형별 결과 해석 데이터를 결합해 다음을 표시합니다.

- 주 유형 카드: 유형 번호, 이름, 영문명, 별칭, 요약
- 핵심 욕구/핵심 두려움
- 날개 유형
- 통합 방향(성장)
- 분열 방향(스트레스)
- 유형별 점수 별형 그래프
- 유형별 점수 막대 리스트
- 긍정적 특성
- 주의할 특성
- 강점
- 성장 포인트
- 핵심 가치와 성장 동기
